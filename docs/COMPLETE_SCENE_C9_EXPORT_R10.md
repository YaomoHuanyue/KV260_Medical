# 原始 CT 新表面：C9 实测与当前场景导出 R10

本轮补齐了候选场景的实际 PL 导航验证和独立完整导出接口。正式默认入口保持原版本，普通肺透明度的实机验收记录继续有效；本轮候选版本尚未经过用户物理验收。整个原 Python 功能补齐目标仍在进行。

## 实际 PL 与 PS 对照

在同一次启动、同一份原始 CT、同一场景包和同一镜头请求下，测试了二值/概率场 × 高/超高精度 × 自动对齐/手动镜头，共 8 组 640×363 请求。每组交替执行三次 ARM 四核 PS 和 C9。深度、法线、目标覆盖及轮廓的每个 64 位输出均一致，四块 DMA 保护区和输入令牌检查均通过。

| 测量范围 | ARM 四核 PS | PL C9 |
|---|---:|---:|
| 完整已预热 API 调用，各组中位数范围 | 913.47–942.22 ms | 84.27–85.61 ms |
| PL 相对 PS 加速倍数 | — | 10.81–11.05 倍 |

这里包含 API 中的数据复制、同步、执行和保护区检查，不包含场景冷准备、上传、文件保存或界面显示。各组冷启动时间、逐次样本、输入与输出校验值另存于测试报告。不能把上述倍数当成完整医疗流程加速倍数。

实际 HDMI 候选界面完成 106 次 PL 图像请求。导航交互窗口显示了 90 次更新，约 11.38 次/秒，更新间隔 P95 102 ms，最大 113 ms；该窗口使用 640×282 的视口，与上表的固定 640×363 测量分开。停止交互后恢复精细画面，完成镜头方向与法线保持配对。截图已检查，不替代用户验收。

已有医疗静态外壳通过显式手动操作加载。先校验独立平台驱动及其时钟/复位配置，再加载应用；没有走旧脚本中的 ZOCL 卸载路径。测试协作退出并恢复 C6，未生成新的位流。

## 当前场景导出

`export_scene_r10.py` 将当前 C1 气道、当前路径和 C9 场景包绑定为同一个版本，并在私有暂存目录中完成校验后一次性发布。导出操作在 PS 上做文件序列化，没有重新运行 PS Marching Cubes，也没有增加 PL 资源。

包内包括当前气道 STL、带法线/分支代数/半径/概率/颜色的 VTP、肺和候选的完整表面、路径 VTP/CSV/JSON、原网格 NIfTI/NRRD 掩膜、候选标签与目录、已有细支气管恢复资料、原始完整分析报告，以及独立的当前场景包。

气道按原顶点 ID 建索引，保留拓扑修复产生的分离顶点；不按位置合并。三角形顺序、坐标、法线和属性与当前显示数据一致。只有起点的受限路径也能导出，但不会虚构可行镜头路径。

原网格的器械比较和 Pareto 报告放在 `original_analysis`，明确标为原分割网格参考；它们不能证明当前新表面的净空。根目录的气道和路径对应当前场景，不再导出旧路径冒充当前路径。独立场景包内只有自身清单要求的文件，不依赖另一个结果目录才能读取几何与镜头数据。

## 验证与边界

- Windows 和 ARM 分别完成 8 组 STL/VTP/CSV 独立读回，包含可导航和只有起点的情况；Windows 另用 VTK 读取器验证 VTP。
- ARM 完整包逐文件校验，NIfTI 与 NRRD 的体素及物理几何一致；错误 CT、截断属性和覆盖已有导出被拒绝。
- Qt 候选界面使用独立导出适配器；操作前协作释放图形计算，后台导出，完成事件检查当前版本和路径身份。
- 初次部署预检发现源清单中缺少一个校验辅助文件，未访问 PL；补齐相同文件后继续。原失败记录和后继构建均保留。

资源仍使用已验收 C9 R7：100 MHz、4 条射线计算通道、通道流水 II=1。整个设计 LUT 46,292、FF 49,672、DSP 328、BRAM36 121、URAM 64。该次导出没有改变这些资源值；当前可重配置区域的 URAM 已用完，BRAM36 等效余量为 11。
