# 原标量表面与导航完整数据包 R8

本版本补齐数据交接层：同一原始标量场、实际 PL C1 网格、新路径、相机、分岔标签和管径提示作为一个版本读取。当前 HDMI 默认界面仍为 R17，尚未接入本包；本版本不宣称已完成界面迁移或新的 C9 实板加速验证。

## 数据与计算

输入来自前序已验证的四种原 Python 表面：二值高精度、二值超精度、网络概率高精度、网络概率超精度。使用原始各向同性与平滑算法，Q5/Q6 标量保持原值；只保留此前已证明不改变零交叉边的远负值饱和。

拓扑来自 R6 实板 C1 提取。R7 仅拆分重合顶点索引，保留每个已保留三角形坐标及顺序。R8 读取这些证据，没有重新运行 PL，也没有 PS Marching Cubes 回退。

PS 完成原标量字段准备、标量边插值、精确几何审核、路径规划、相机和分岔标签准备，以及 R8 打包/校验。概览网格法线在 PS 上计算；C9 的导航管壁法线由其现有 PL 核心计算。新增接口不增加 PL 核心或硬件资源。

每份包包含 `mesh.npz`、`airway.vertices`、`route.npz`、`route.json`、`camera.npz`、`guidance.json`、`hud.json`、中性和分岔 `scene_*.bin` 以及完整 `scene.json`。标量已完整编码到稀疏 C9 数据包，读取时逐体素解包核对，不另存一份大型密集标量数组。运行时不依赖包外的网格、路径或标量文件。

生产者验证前序源码/输入/实际 C1 提取证据。包内身份绑定网格坐标、标量、路径统计、器械参数、相机、引导和全部负载文件 SHA。发布前完成完整校验，再一次性重命名目录；不能把半成品作为可用场景读取。

路径仍需实际管壁、裁剪面及源掩膜区间审核。1 mm 弯曲约束的四组路径均为 891 点、约 169.44 mm、有限到达；不能把“可沿此路线前进”解释为已到达病灶。10 mm 约束的根点路径不产生前进相机或出口标记。几何自接触、临床有效性和器械接触安全并未由本包认证。

## 帧交接

`SceneSnapshot` 在启动阶段校验并读取一个完整版本。每帧只查询已经准备的弧长、镜头、引导区间和 HUD，不重复哈希体积、不重新打包，也不重新计算曲率。

实际手动 yaw/pitch 后的相机方向由请求传入，渲染与联动总览必须使用该次完成帧的相同镜头。`LatestFrameQueue` 保持一个执行帧和一个最新待执行视角，丢弃过期结果；执行帧结束前拒绝更换场景。此队列接口已测试，尚未替换 R17 Qt 传输线程。

`quality_worker_r8.py --prepare-only` 只校验和输出完整交接合同，不访问 PL。真正渲染入口使用现有已验收 C9，会先检查当前固件是否为医疗静态外壳；本适配器不加载静态外壳、不卸载 ZOCL、不设置自动启动。

## 验证范围与后续

四种表面分别验证可行路径和根点路径。C9 场景的标量及标签跨平台要求字节一致；网格坐标和索引完全一致；路径及相机允许 1e-10 的浮点差异，概览法线允许 1e-6。

参考渲染使用 640×363、最多 1023 步，分别保留自动对齐和手动转动镜头。PS1/PS4 全像素 64 位结果必须完全一致，包括深度、管壁法线、目标覆盖与轮廓。冷态密集解包另列，渲染计时不代表界面帧率。

后续需让原生 Qt 界面一次性交接概览网格、路径、相机、提示和引导；对新包复用同一批请求完成实际 C9/最强 PS 对照、DMA 保护区检查和实机交互验收。新数据源只能由明确操作选择，不能在进入导航几秒后自动换模型。其余原 Python 功能与性能目标仍以总进度账本为准。
